# Simple Tasker — фронтенд

Русскоязычный адаптивный интерфейс к текущему Spring Boot API. React + TypeScript,
Vite для разработки и сборки, обычный CSS. В production-зависимостях только React
и React DOM. Запросы выполняются через встроенный `fetch`; отдельный роутер,
хранилище состояния и библиотека UI для одного экрана не нужны.

## Запуск

Нужен Node.js 22.12+ или 24+ и запущенный бэкенд с PostgreSQL.
Запуск существующего Docker Compose описан в корневом README.

```sh
cd frontend
npm ci
npm run dev
```

Открыть http://127.0.0.1:5173. Данные хранятся в базе бэкенда; интерфейс не
подставляет демонстрационные задачи и не сохраняет задачи в localStorage.

При другом адресе бэкенда создать `frontend/.env.local`:

```dotenv
API_PROXY_TARGET=http://localhost:8081
```

Можно скопировать `.env.example` в `.env.local` и изменить значение.
После изменения перезапустить Vite. Корневой `.env` Docker Compose автоматически
не читается: если изменён `APP_PORT`, нужно указать такой же порт здесь.
`API_PROXY_TARGET` используется процессом Vite и не включается в браузерный JavaScript.

## Граница между браузером и бэкендом

```text
Браузер → http://127.0.0.1:5173/api/v1/tasks
        → Vite proxy → http://localhost:8080/api/v1/tasks
        → Spring Boot → PostgreSQL
```

Браузер запрашивает UI и API у одного origin — одинаковых схемы, хоста и порта.
Поэтому в этом режиме не требуется менять CORS в Spring. Vite перенаправляет
`/api` без удаления префикса. Если браузер будет обращаться прямо к другому
origin бэкенда, понадобится явная настройка CORS на бэкенде.
Подробнее: [Vite server.proxy](https://vite.dev/config/server-options.html#server-proxy).

| Действие | HTTP-запрос |
| --- | --- |
| Список | `GET /api/v1/tasks?sortBy=CREATED_AT&sortMode=DESC&page=0&size=10` |
| Фильтр | Тот же запрос с `status=NEW`, `IN_PROGRESS` или `DONE` |
| Детали | `GET /api/v1/tasks/{id}` |
| Создать | `POST /api/v1/tasks`, JSON `{title, description}` |
| Изменить | `PATCH /api/v1/tasks/{id}`, JSON `{title, description}` |
| Удалить | `DELETE /api/v1/tasks/{id}`, ответ `204 No Content` |
| Взять в работу | `POST /api/v1/tasks/{id}/start` |
| Завершить | `POST /api/v1/tasks/{id}/complete` |

Список читается из `PageResponse.items`, страницы в запросах нумеруются с нуля.
Фильтрация, сортировка и пагинация выполняются сервером, а не только среди
загруженных строк. В интерфейсе дата отображается в часовом поясе браузера.

Особенности текущего контракта:

- Список возвращает `TaskShortDto` без описания. При открытии задачи выполняется
  отдельный GET за `TaskFullDto`.
- Название обязательно, максимум 127 символов; описание — максимум 2047.
  PATCH использует тот же DTO с `@NotBlank`, поэтому отправляем название даже при
  изменении только описания. Для очистки описания отправляем `""`: `null` сервис
  воспринимает как отсутствие изменения.
- Допустимы только переходы `NEW → IN_PROGRESS → DONE`. Кнопки соответствуют
  этим переходам; при HTTP 409 можно перечитать актуальную задачу.
- После успешной записи список и счётчики запрашиваются заново. Незавершённые
  запросы списка отменяются при смене фильтра, чтобы старый ответ не заменял новый.
- Для счётчиков выполняются три GET с `size=1` и разными статусами: используем
  `totalElements`. Это небольшая дополнительная нагрузка вместо нового API.
  Запросы независимы, поэтому счётчики не являются атомарным снимком при
  одновременных изменениях другими клиентами. При ошибке показывается «—».
- Удалить можно задачу в любом статусе из окна её просмотра, после подтверждения.
  Ответ `204` не содержит JSON. После удаления обновляются список и счётчики;
  если последняя страница опустела, открывается предыдущая доступная страница.
  При `404` на DELETE показывается «Задача уже удалена» и данные перечитываются.
  При других ошибках окно остаётся открытым для повторной попытки.
- Поиск, проекты, пользователи и обратные переходы статуса отсутствуют
  в текущем API и не добавлены в интерфейс.

## Сборка и просмотр

```sh
npm run build
npm run preview
```

`build` проверяет TypeScript и создаёт `dist/`. Preview доступен на
http://127.0.0.1:4173 и использует такой же прокси для локальной проверки сборки.

Vite dev/preview — локальные инструменты, не production-сервер.
В production нужно раздавать `dist/` как статические файлы и направлять `/api`
в Spring Boot на том же публичном origin. Прокси из `vite.config.ts` **не входит
в dist**. Для `index.html` стоит предусмотреть перепроверку кеша, для файлов
`assets/` с хешами — длительное кеширование; ответы API не следует кешировать
на reverse proxy. Production-развёртывание, Nginx, Dockerfile фронтенда и изменения
Compose в эту работу не включены.

## Проверки

```sh
npx playwright install chromium
npm test
```

Playwright запускает настоящий Chromium и отдельный Vite на порту 5174.
HTTP-запросы `/api/v1/tasks` перехватываются в браузере: React, формы, фокус,
fetch и отображение настоящие, Spring и БД заменены тестовым обработчиком.
Реальные задачи не создаются. Тесты не доказывают интеграцию с запущенным Spring.

Одинаковые сценарии проверяются на настольном и мобильном размере:
пагинация и фильтры, сортировка, создание, очистка описания через PATCH,
последовательность статусов, ошибки и повторная загрузка, сохранение черновика,
защита от повторной отправки, HTTP 409, запоздавший ответ, клавиатурное закрытие
диалога и безопасное отображение текста пользователя.
Также проверяются подтверждение и отмена удаления, пустой ответ `204`, удаление
во всех статусах, обновление счётчиков, переход с опустевшей страницы, ошибка
с повторной попыткой и `404`, если задачу уже удалил другой клиент.

При падении trace сохраняется в `test-results/`.
Для ручной проверки с реальным API: создать задачу, открыть и изменить описание,
взять в работу, завершить; затем обновить страницу и проверить результат.

## Файлы

- `src/api.ts` — типы текущего контракта, fetch и обработка ошибок.
- `src/App.tsx` — список, фильтры, счётчики и пагинация.
- `src/TaskDialog.tsx` — просмотр, создание, редактирование, удаление и смена статуса.
- `src/ui.tsx` — небольшие общие элементы интерфейса и форматирование дат.
- `src/styles.css` — оформление и адаптивность без внешних шрифтов и CDN.
- `vite.config.ts` — адрес и прокси локального сервера.
- `tests/tasks.spec.ts` — браузерные проверки контракта и поведения.
